# Doc Kinds Manifest

Kind definitions consumed by `kusara`. The CLI loads `${KUSARA_DOC_ROOT}/kinds.md`
at startup (default `KUSARA_DOC_ROOT=docs`); the YAML block below is the source
of truth.

Schema semantics (`related` / `modules` / etc.): [`.claude/rules/refs.md`](../.claude/rules/refs.md).

## Adding a new kind

1. Add an entry to the YAML block.
2. Add `index.output` if a generated INDEX is wanted.
3. Run `kusara validate`.

## Manifest

```yaml
# Each entry is a kind definition.
#   name        — kind identifier used as the `kind:` field in front matter
#                 and as the prefix in `id:` (e.g., kind=fr → id=fr:01-...).
#   path_globs  — repo-relative globs the scanner walks.
#   id_pattern  — informational; what an ID for this kind looks like.
#   declared_via — "generated" for kinds written only by `kusara index`.
#   index       — when set, `kusara index` writes a generated INDEX for this
#                 kind to index.output.
kinds:
  - name: fr
    # Functional requirement pages: docs/fr/01-foo.md, 02-bar.md, ...
    # `[0-9]*` excludes README.md, _template.md, and index.md.
    path_globs: ["docs/fr/[0-9]*.md"]
    id_pattern: "fr:{slug}"
    index:
      output: docs/fr/index.md

  - name: reference
    # `[a-z]*` excludes README.md (uppercase). The generated index.md is
    # matched but carries its own `kind: index` frontmatter.
    path_globs: ["docs/reference/[a-z]*.md"]
    id_pattern: "ref:{slug}"
    index:
      output: docs/reference/index.md

  - name: index
    # Files written by `kusara index`; never hand-edited.
    declared_via: generated
    id_pattern: "index:{kind}"
```

## Reserved kind: `index`

Files generated by `kusara index` carry `kind: index` and are never
hand-edited.
